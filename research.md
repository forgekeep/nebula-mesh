## Findings

### Go-библиотека nebula/cert

- Пакет `github.com/slackhq/nebula/cert` предоставляет полный API для PKI: создание CA, подписание сертификатов, валидация, blocklist, шифрование ключей (AES-256-GCM + Argon2id)
- `TBSCertificate.Sign()` — подписание сертификата CA-ключом, `SignWith()` — делегирование подписания внешнему signer (HSM/PKCS#11)
- `CAPool` — пул CA для верификации и blocklist management
- `Certificate` interface поддерживает v1 (IPv4) и v2 (IPv4+IPv6) форматы
- Curve: `Curve_CURVE25519` (default) и `Curve_P256` (для PKCS#11)
- Nebula `cmd/nebula-cert/` — reference implementation для CA creation (`ca.go`), signing (`sign.go`), verification (`verify.go`)

### Архитектура Defined Networking

- **Pull-модель**: DNClient опрашивает backend каждые ~60 секунд через REST API
- **Enrollment**: одноразовые токены через `POST /v1/host-and-enrollment-code`
- **Аутентификация API**: Bearer token с гранулярными scope
- **DNClient**: проприетарный, переиспользовать нельзя — нужен свой агент
- Конфигурация, сертификаты, blocklist доставляются через pull

## Constraints & Risks

| Ограничение / Риск | Severity | Влияние на реализацию |
|---------------------|----------|-----------------------|
| PKCS#11 только P256 (не Curve25519) | Medium | MVP на Curve25519 без HSM, P256+HSM — отдельная фича |
| Mobile Nebula требует форк для auto-management | High | MVP без мобильных, ручная настройка через UI приложения |
| Nebula blocklist не распространяется через lighthouse | High | Agent обязан получать blocklist через poll |
| `nebula/cert` API может меняться между версиями | Medium | Зафиксировать версию nebula в go.mod |
| Нет встроенного push — только pull | Low | Pull каждые 30-60с достаточен |
