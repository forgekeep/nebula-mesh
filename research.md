## Findings

### Store Layer (`internal/store/sqlite.go`)

- **SQL injection в ListAuditEntries** — `fmt.Sprintf(" LIMIT %d", limit)` вместо параметризованного запроса (`sqlite.go:517`). Хотя `limit` приводится к int через `strconv.Atoi` в `audit.go:16`, паттерн нарушает security conventions
- **RowsAffected ошибка игнорируется** — `rows, _ := result.RowsAffected()` в UpdateHost (`sqlite.go:268`) и DeleteHost (`sqlite.go:280`). При ошибке `rows=0`, что маскируется как ErrNotFound
- **LIKE injection в фильтре групп** — `args = append(args, "%\""+filter.Group+"\"%")` (`sqlite.go:228`). Спецсимволы `%`, `_` в имени группы ломают LIKE паттерн
- **Корректный паттерн** в том же файле: другие Exec проверяют ошибки корректно (`sqlite.go:264-266`)

### Agent Layer (`internal/agent/`)

- **signalNebula отправляет SIGHUP на PID 1** (`poller.go:134`). `os.FindProcess(1)` — init/systemd, не nebula. Комментарий "placeholder" подтверждает незавершённость. Config уже имеет поле `NebulaPIDFile` (`config/agent.go:17`), но оно не используется
- **Fingerprint не URL-escaped** в query param (`poller.go:68`). `fmt.Sprintf("...?fingerprint=%s", p.fingerprint)` — спецсимволы сломают URL. Тесты используют безопасные значения (`poller_test.go:18`)

### CLI Layer (`internal/cli/`)

- **Migrate(nil)** — nil context вместо `context.Background()` (`init.go:76`). В `serve.go:62` используется корректный `context.Background()`. Текущая реализация Migrate не использует контекст (`sqlite.go:53`), но контракт интерфейса требует его (`store.go:62`)
- **JSON ошибки игнорируются массово**: `json.Marshal` (`host.go:27`, `network.go:17`), `json.Unmarshal` (`host.go:50`, `network.go:39`), `json.NewDecoder.Decode` (`host.go:80`)

### Web Handlers (`internal/web/handlers.go`)

- **handleHostBlock** (`handlers.go:205-222`) — stale read-write: GetHost → AddToBlocklist → UpdateHost без транзакции. Ошибки AddToBlocklist и UpdateHost игнорируются. Частичное выполнение оставляет инконсистентное состояние
- **handleHostDelete** (`handlers.go:224-234`) — `host, _ := w.store.GetHost(...)` ошибка через `_`. AddToBlocklist и DeleteHost ошибки игнорируются
- **Массовое игнорирование store ошибок**: ListNetworks (`handlers.go:59,119,239`), ListHosts (`handlers.go:62,82`)
- **strconv.Atoi ошибка** — `listenPort, _ := strconv.Atoi(...)` (`handlers.go:129`), невалидный порт молча становится 0
- **rand.Read без проверки** — `rand.Read(b)` в `generateToken()` (`session.go:99`). При сбое RNG — предсказуемый токен

### API Layer (`internal/api/`)

- **Enrollment: UpdateHost после ответа** — `writeJSON` отправляет 200 OK, затем UpdateHost может упасть (`enroll.go:142-144`). Клиент видит успех, но статус/fingerprint не сохранены
