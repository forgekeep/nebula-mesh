## Goal

[~] Создать self-hosted платформу для управления Nebula mesh-сетью: management server с REST API и агент для хостов. Два этапа: MVP (PKI engine, enrollment, config generation, agent) и Phase 2 (Web UI, auto-renewal, lighthouse management).

## Strategy

Монорепо на Go с single module. Два бинарника: `nebula-mgmt` (management server) и `nebula-agent` (агент на хостах). Shared code в `internal/`. PKI через прямой import `nebula/cert` Go-библиотеки — без вызова `nebula-cert` binary.

Enrollment по модели Defined Networking: администратор создаёт хост через API → получает одноразовый token → агент на устройстве использует token для получения сертификата и конфигурации. Агент опрашивает сервер каждые 30 секунд для обновлений (cert renewal, config changes, blocklist).

[~] Go 1.26 (latest stable). Storage — SQLite через `modernc.org/sqlite` (pure Go, без CGO). API — стандартная библиотека `net/http` + chi router. Минимум зависимостей.

## Devil's Advocate

### Reversibility/Magnitude

| Decision | Reversibility (1-5) | Magnitude (1-5) | Risk | Mitigation |
|----------|---------------------|-----------------|------|------------|
| Single module monorepo | 2 | 3 | При росте сложно разделить shared code | internal/ чётко разграничивает boundaries; split позже через go.work |
| SQLite storage | 2 | 3 | Не масштабируется при concurrent writes | Абстракция через store interface, замена на PostgreSQL без изменения API |
| Token-based enrollment | 1 | 4 | Архитектура enrollment пронизывает agent и server | Token model проверена DN (100+ хостов на free tier), достаточна для наших масштабов |
| Agent как отдельный процесс (не embedded) | 3 | 4 | Два процесса вместо одного, сложнее lifecycle | Проще отладка, независимые обновления; embedded возможен позже |

### Top-3 Failure Modes

1. **Потеря CA private key** — если сервер с intermediate CA теряет данные, вся сеть требует пересоздания. Mitigation: encrypted backup CA key при создании, отображение напоминания в CLI.
2. **Agent не может достучаться до server** — при недоступности management server агенты продолжают работать со старыми сертификатами, но не получают обновления blocklist. Mitigation: длинный TTL сертификатов (30 дней), агент логирует предупреждения.
3. **Race condition при concurrent enrollment** — два агента одновременно используют один token. Mitigation: token stored with UNIQUE constraint, enrollment в транзакции.

### Inversion Check

Чтобы гарантировать провал: хранить CA key в открытом виде, не валидировать enrollment tokens, не логировать ошибки, игнорировать expiry сертификатов.
Значит: шифровать CA key, валидировать token одноразовость в транзакции, structured logging на всех уровнях, проверять expiry при каждом poll.
