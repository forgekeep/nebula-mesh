### Top-3 Failure Modes

1. **CA rotation persistence: passphrase не совпадает при reload** — после ротации сервер пишет новый CA с текущим passphrase. При рестарте serve.go запрашивает passphrase у пользователя. Если пользователь введёт другой — не загрузится. Mitigation: passphrase тот же (вводится при старте сервера), не меняется.
2. **Firewall CRUD: JSON в network_config не парсится** — если кто-то вручную записал невалидный JSON в таблицу. Mitigation: getFirewallRules возвращает defaults при ошибке парсинга + логирование.
3. **signalNebula: PID file не существует при первом запуске** — агент стартует раньше nebula. Mitigation: возвращаем ошибку с логированием, не паникуем. Следующий poll-цикл повторит.

### Inversion Check

To guarantee failure, we would: ignore errors silently, skip input validation, never persist CA to disk, send signals to wrong processes, store invalid data.
Therefore, we must ensure: every error checked and propagated, input validated at entry point, CA persisted immediately after rotation, PID read from file, CIDR/IP validated at creation.
